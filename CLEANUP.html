• Codebase Cleanup Report
    • Security Risks
      • Unsafe environment parsing enables code injection
        • Reference: apps/api/config/config.py:120
        • Impact: Using eval() on LEARNHOUSE_DEVELOPMENT_MODE lets anyone controlling that environment variable execute arbitrary Python.
        • Recommendation: Replace eval() with explicit string-to-bool parsing (e.g. distutils.util.strtobool) and provide a safe default.
      • Default admin credentials ship in tooling
        • Reference: apps/api/cli.py:60, load_test2/user_test.py:21
        • Impact: Installer and load test scripts hard-code production-like admin credentials, risking compromise if leaked or reused.
        • Recommendation: Require credentials via environment variables or prompts and strip secrets from version control.
      • Automatic installer can recreate weak admin accounts
        • Reference: apps/api/src/core/events/autoinstall.py:21
        • Impact: Empty databases trigger install(short=True), reinstating default data and weak admin credentials.
        • Recommendation: Remove auto-install or gate it behind an explicit feature flag with secure credential prompts.
      • JWT config downgrades secrets and disables expiry
        • Reference: apps/api/src/security/auth.py:21-26
        • Impact: authjwt_secret_key defaults to "secret" in dev mode and access token expiry uses a float, potentially never expiring.
        • Recommendation: Always load secrets from configuration, fail fast when missing, and pass a timedelta to FastAPI-JWT Auth settings.
      • Password reset leaks credentials through URLs
        • Reference: apps/web/services/auth/auth.ts:88, apps/api/src/routers/users.py:231
        • Impact: Frontend sends new_password via query string, exposing plaintext passwords in logs and intermediaries.
        • Recommendation: Move reset parameters into a JSON body over HTTPS and keep sensitive values out of URLs.
      • Embed sanitisation allows arbitrary attributes
        • Reference: apps/web/components/Objects/Editor/Extensions/EmbedObjects/EmbedObjectsComponent.tsx:41-44
        • Impact: DOMPurify configured with ADD_ATTR: ['*'] re-enables dangerous event attributes and allows stored XSS.
        • Recommendation: Whitelist only required attributes (e.g. src, allow, frameborder) and rely on DOMPurify defaults otherwise.
      • Middleware sets cookies for .localhost only
        • Reference: apps/web/middleware.ts:75-83
        • Impact: Production domains never receive learnhouse_current_orgslug cookie, breaking auth flows.
        • Recommendation: Derive cookie domain dynamically from request host and omit domain attribute in development.
    • Reliability & Design Smells
      • Type coercion in config breaks falsy values
        • Reference: apps/api/config/config.py:334-360
        • Impact: bool("false") is True and list(allowed_origins) fails when None; ports default to empty strings causing crashes.
        • Recommendation: Parse booleans/ints explicitly, default allowed_origins to [], and validate config via Pydantic.
      • Database schema mutates at import time
        • Reference: apps/api/src/core/events/database.py:32-48
        • Impact: Importing the module triggers recursive imports and SQLModel.metadata.create_all, modifying schema unexpectedly.
        • Recommendation: Move model discovery and migrations into startup hooks or tooling; keep module imports side-effect free.
      • Async services block the event loop
        • Reference: apps/api/src/services/users/users.py:37-116
        • Impact: async handlers call Session.exec and commit synchronously, blocking FastAPI event loop under load.
        • Recommendation: Adopt SQLModel async engine/session or run sync work via run_in_threadpool.
      • Runtime configuration utilities rely on brittle hacks
        • Reference: apps/web/services/config/config.ts:12-92
        • Impact: Dynamic env var name rebuilding and returning "error" strings make builds fragile and leak details.
        • Recommendation: Standardise config loading with schemas, remove string splicing hacks, and fail fast when env vars are missing.
      • Middleware contains placeholder error handling
        • Reference: apps/web/middleware.ts:149
        • Impact: throw("This is broken") returns opaque 500 errors, hindering production diagnostics.
        • Recommendation: Replace placeholders with structured errors or redirects and add test coverage.
    • Redundant & Versioned Assets
      • Checked-in dependencies inflate the repo
        • Reference: node_modules/.modules.yaml:1, apps/web/node_modules/.modules.yaml:1
        • Impact: Committed node_modules slow clones and hide dependency provenance.
        • Recommendation: Delete node_modules from source control and rely on lockfiles plus CI installs.
      • Conflicting lockfiles
        • Reference: apps/web/package-lock.json:1, apps/web/pnpm-lock.yaml:1
        • Impact: Maintaining npm and pnpm locks causes drift and wasted builds.
        • Recommendation: Standardise on one package manager (pnpm) and remove the other lockfile.
      • Stale orchestration artefacts
        • Reference: docker-compose.yml.old:1
        • Impact: Legacy compose file confuses operators and risks drift from supported deployments.
        • Recommendation: Archive or delete legacy file once documented elsewhere.
      • Load-test scaffolding mixes prod credentials
        • Reference: load_test2/user_test.py:1-140
        • Impact: Bespoke tooling with hard-coded hosts and secrets belongs outside the main repo.
        • Recommendation: Move scripts to a private ops repo or gate them behind opt-in configuration.
    • Software Engineering Debt
      • Configuration is recomputed on every call
        • Reference: apps/api/config/config.py:108, apps/api/src/services/dev/dev.py:5, apps/api/src/security/security.py:7
        • Impact: Helpers repeatedly reload YAML and environment variables, adding filesystem overhead.
        • Recommendation: Cache parsed configuration with a singleton or lru_cache and inject settings.
      • Auth scaffolding is inconsistent and mostly dead code
        • Reference: apps/api/src/security/auth.py:16, apps/api/src/security/auth.py:43-49
        • Impact: OAuth2PasswordBearer points at /api/auth/login while router lives under /api/v1, and dependency is unused.
        • Recommendation: Fix token URL, wire dependency into endpoints, or delete unused scaffolding.
      • Password hashing utilities are contradictory
        • Reference: apps/api/src/security/security.py:5-17
        • Impact: bcrypt CryptContext is initialised but helpers call pbkdf2_sha256 directly, creating confusion.
        • Recommendation: Standardise on one hashing strategy and remove unused context setup.
      • User service is a 600+ line grab bag
        • Reference: apps/api/src/services/users/users.py:1-600
        • Impact: Mixed responsibilities and stringified timestamps hinder reasoning and testing.
        • Recommendation: Split module into cohesive units, use timezone-aware datetimes, and add targeted tests.
      • Production code still emits ad-hoc prints
        • Reference: apps/api/src/core/events/database.py:28, apps/api/app.py:69
        • Impact: print statements leak internal paths and bypass structured logging.
        • Recommendation: Replace prints with shared logger or Python logging, gating noisy messages behind debug levels.
      • Type safety on the frontend is effectively disabled
        • Reference: apps/web/services/auth/auth.ts:4-18
        • Impact: Literal 'string' types and any parameters remove TypeScript guardrails.
        • Recommendation: Define real interfaces, remove any, and share types with backend where possible.
      • Automated coverage is almost nonexistent
        • Reference: apps/api/src/tests/test_main.py:1-49
        • Impact: Only two backend tests cover a single happy path, leaving critical logic untested.
        • Recommendation: Establish baseline unit and integration tests and wire them into CI.
